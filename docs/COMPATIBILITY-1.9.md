# Bitchord+ patches vs BitChord 1.9 (`v1.8.2` branch @ e523218e)

Imported source review from the supplied beta.7 bundle. Baseline: BitChord tag
`v1.8.1`. This review does not add BitChord 1.9 support to beta.7; its supported
application target remains 1.8.1.
Method: source diff of every class, method, string and field that a hook or an extension reflection touches. The hooks run against R8-optimised dex, and some of them pin register counts or R8 merge artifacts (merged lambda/coroutine classes, `ExternalSyntheticLambdaNN` indexes, `TypesJVMKt` hosting Compose's `painterResource`, renamed `AudioBlock` fields). Source alone cannot confirm those, so they are marked "may break" whenever the surrounding code changed or the anchor is an R8 artifact.

Notes before the table:
- `build.gradle.kts` at e523218e says versionName `1.9`, versionCode 34, beta suffix **`beta3`** (not beta2).
- Every patch declares `AppTarget(version = "1.8.1", isExperimental = true)` (TelegramPatch.kt:78). `1.9` has to be added, or the patcher will flag the APK as unsupported.
- New in 1.9 `proguard-rules.pro`: `-assumenosideeffects android.util.Log`. The string anchors we use (`TrackLog`, `DebugLog` → app sink) are **not** android.util.Log, so they survive.

## 1. Hook verdicts

### Breaks (fails at patch time, or the feature silently stops)

| # | Hook (file:line) | Verdict | Why |
|---|---|---|---|
| 1 | Patches & tweaks section, `extrasSettingsPatch` (PatchesUiPatch.kt:110-121) | **likely breaks** | In 1.9 `SearchableSettingsGroup` is `private inline fun` (SettingsSheet.kt:2263). No `SearchableSettingsGroup-*` call is left in `SettingsScreen-*`, so `groups.size >= 3` fails ("Settings groups not found"). Every optional extras patch depends on this one, so **all of Sing / Pitch / Loudness / Sleep fade / Battery saver / Download quality / Headphone / Output EQ / DJ / JamesDSP / Lossless-BT fail to apply**. Fix: anchor on the first `SettingsGroup-*` call inside `SettingsScreen-*` (the inlined account card, in the `section == null` branch), or right after the `SettingsCategoryList` call (SettingsSheet.kt:574), and take the composer from that call. |
| 2 | Smooth quality upgrade, step 1 (TelegramPatch.kt:511-533, entry 597-653) | **likely breaks** | The `smoothSwapCurrentTrackVersion$1` coroutine now also captures `measureAlignment: Boolean` and `officialMap: VersionTimeMap?` (PlaybackService.kt:2219-2225; YouTube's official version time maps). The 9-parameter constructor check fails ("Version swap parameters changed"). They never run because step 1 throws first. | 3 | Format legend after song titles (TelegramPatch.kt:916-931) | **likely breaks** | `ExplicitSongTitle` already uses `Modifier.weight(1f, fill = false)`, twice (fade and plain branches, SongText.kt). Fix: drop the weight rewrite (upstream already does it) and make it optional. Also note the legend lands only on the non-fading branch, so it will not show where 1.9 passes `fadeOverflow = true` (players). |
| 4 | Stats overlay `SleeveNerdStats` (TelegramPatch.kt:1604, 1648-1657) | **likely breaks** | 1.9 adds an `automixDetail` state read and a `when` branch, and changes `maxLines = 1` to `maxLines = 2` (PlayerControls.kt). `registerCount == 50` is very likely wrong, and the "v17 == 1 maxLines" check fails for certain. | 5 | Audio tap: Sing, Headphone correction, DJ analysis (TelegramPatch.kt:1806-1817) | **likely breaks** | PrecisionAudioSink now runs `dspChain.process(audioBlock)` twice: `handleBuffer` (line 412) and the new Automix `generateLoop` (line 591). | 6 | Telegram -> Library playlist (`HostLibrary.songs`, extension HostLibrary.java:24-52, 70-74) | **likely breaks (runtime)** | `Song` gained a 28th constructor parameter, `feedbackToken: String?` (Models.kt). `SONG_PARAMETERS` has 27 entries and the match is exact, so it throws "This BitChord version can't take songs from the patch." Fix: append `"String"` (or match a prefix and pad nulls). |
| 7 | Telegram downloads (NativeDownloads via the merged `fetchDirect`, TelegramPatch.kt:1204-1256) | **likely breaks (behaviour)** | 1.9 `Downloads.keepable()` calls `Downloader.probe(url)` on **every** source candidate, using OkHttp with a Range GET, before a route may win (Downloads.kt:1467). A `https://telegram.bitchord.invalid/...` URL never resolves, so `probe` returns null. Telegram is skipped for matched downloads (falls to JioSaavn/YouTube), and a download of a Telegram row (`fromRow`) ends with "Couldn't download this song from Unofficial Telegram". The `fetchDirect` hook is never reached. Fix: hook `Downloader.probe` (or its `withContext` body) so that for `InternalAddon.reserved(url)` it returns `Probe.File(container from NativeDownloads' first bytes, size)`. |

## 2. Feature overlaps with 1.9

| Our feature | 1.9 feature | With both on | Suggested fix |
|---|---|---|---|
| **Sing, Headphone correction (AutoEq), DJ key/tempo learning** (PrecisionAudioSink tap) | **Bit-perfect output** (`BitPerfectRoutingSink` in front of PrecisionAudioSink: USB_DIRECT via libusb, DAP_EXCLUSIVE AAudio, Android 14 USB mixer) | A bit-perfect track skips DspChain entirely, so Sing, AutoEq and the downmix do nothing and DJ mode learns nothing from it. Upstream says so in `bit_perfect_sheet_warning`. | On the Patches & tweaks page, show "bypassed while bit-perfect is active" (read `AppSettings.bitPerfectMode` and `BitPerfectOutput.ready`). Optionally, when Sing or AutoEq is on, make `BitPerfectAudioSink.canAccept` return false (one hook) so those tracks take the normal path. |
| **Sing / AutoEq** | **Automix loop mix** (`generateLoop`, signalsmith-stretch decks rendered inside the sink) | Even after #5 is fixed at one site, the loop-mix stretch (often 8-32 bars) is processed by DspChain but not by our tap. Vocals come back and AutoEq drops out mid-transition. | Hook both `dspChain.process(audioBlock)` sites (#5). |
| **Pitch (separate from speed)** | signalsmith-stretch / loopmix_jni | No duplicate. The stretch is only Automix's beat-matching tempo ramp between decks, not a user pitch control. Our pitch is set through player PlaybackParameters, which still apply after the sink. With bit-perfect active, `BitPerfectAudioSink.setPlaybackParameters` is a no-op, so pitch silently does nothing. | Same "bypassed" notice. Nothing else to do. |
| **Loudness target level** | Bit-perfect | Loudness normalisation is bypassed for bit-perfect tracks (stated upstream). Our level is moot there. | Notice only. |
| **Sleep-timer fade** | Sleep timer: only adds custom durations (5-720 min slider). **No fade upstream.** Bit-perfect ignores `setVolume` | The fade is not duplicated. With bit-perfect, `player.setVolume` does nothing, so the song plays at full level for the fade time, then pauses abruptly. | When bit-perfect is active, skip the fade and pause at once, or fade through the DAC volume (`DacVolume`/`UsbVolume`, which needs a hook). |
| **Battery saver (hardware offload)** | Bit-perfect, Automix loop mix, Direct Source Stream | Offloaded (compressed) streams always go to the normal sink (`canAccept` needs `AUDIO_RAW`), so battery saver quietly defeats bit-perfect for any format the chip offloads. It also skips PrecisionAudioSink, so the loop mix cannot splice. | In `SoundExtras.applyOffload`, refuse when `bitPerfectMode != OFF`, and say so. Keep the existing "speed changed" style guard, and also hold offload while Automix is on. |
| **Lossless addons over Bluetooth** | `SourceRegistry.addonsLeftOutOfDownloads()` / `download_addon_needs_lossless_output` notice, `AddonBlockedAlert` | Consistent: our getter override returns false, so 1.9 neither excludes the addon nor shows its "needs lossless output" notice. | None. |
| **Telegram source (as an ADDON-kind config)** | Stricter quality ceiling: `SourceRegistry.permitsForPlayback` now also blocks **tapping an addon row** in Addons search (MainActivity.kt:3572-3575, `AddonBlockedAlert`) and drops upgrades from it (PlaybackService.kt:4795) unless the effective quality is Lossless | Telegram results show as blocked, with "Songs from Unofficial Telegram only play at Lossless", whenever Wi-Fi/cellular quality is High or below, even for MP3/AAC files. | Exempt the Telegram config id in `permitsForPlayback` (one hook), or register the Telegram source with a kind whose `canServeLossless` matches the row. |
| **Telegram downloads** | Download probe (see #7) | Telegram never wins a download. | Hook `Downloader.probe` for reserved hosts. |
| **Smooth quality upgrade (SmoothUpgrade/VersionAlign)** | YouTube official version time maps (`versionTimeMap`), **Direct Source Stream** (`DirectSourceGate`: plays the top-ranked addon from the first note, holding reads until about 25 s before transition) | With Direct Source on, most addon tracks never upgrade, so our crossfaded swap matters less. Optionally skip VersionAlign's measurement when `officialMap != null`. |

## 3. Priority fix list
1. PatchesUiPatch anchor (#1). It blocks every optional patch.
2. SmoothUpgrade constructor (#2).
3. Audio tap with multiple sites (#5); FormatLegend weight (#3); SleeveNerdStats (#4).
4. Extension: `SONG_PARAMETERS` + `"String"` (#6); a `Downloader.probe` hook for reserved Telegram URLs (#7); a `permitsForPlayback` exemption for Telegram.
5. Make the R8-merge lookups class-name independent (#8, #10-#16).
6. Add `AppTarget("1.9")`.
